# 微服务故障根因定位工具 (RCA)

面向卡丁车场计时、预约、会员、支付、直播等数十个微服务的故障根因定位系统。
根据服务调用关系与多维指标,在依赖图上做相关性加权随机游走,输出带依据的根因排名,
并提供可视化页面展示完整分析过程。纯 Go 标准库实现,无外部依赖。

## 快速开始

```bash
# 跑全部 420 个故障场景,输出命中率并与纯异常分排序对照
go run ./cmd/rca run

# 导出详细报告 JSON
go run ./cmd/rca run --retain 420 --out reports.json

# 启动可视化页面(http://localhost:8080)
go run ./cmd/rca server
go run ./cmd/rca server --addr :9000 --retain 60

# 调试单个场景(打印异常分、访问概率、排名、故障簇)
go run ./cmd/rca debug 304

# 单元测试(含命中率回归门限、可复现性、窗口检测精度)
go test ./...
```

## 系统结构

```
cmd/rca/            命令行入口(run/server/debug)+ 内嵌 Web 页面
internal/model/     共用数据结构(服务、调用记录、故障、异常分、排名、报告)
internal/graph/     从调用记录自动构建依赖图,图遍历(有向/无向最短路径)
internal/sim/       32 服务拓扑生成、指标时序模拟、四类故障注入与沿链传导
internal/detect/    基线对比异常检测、故障时间窗口识别、纯异常分基线排序
internal/rca/       指标相关性、故障簇切分、随机游走、来源判定、证据生成
internal/eval/      420 场景批量实验、命中率统计、与注入记录逐条核对
```

## 算法流程(对应需求 1~8)

1. **依赖图自动构建**: 聚合逐 tick 的 RPC 调用记录,边上带累计调用量、
   每 tick 平均流量、加权平均延迟与错误率。
2. **基线异常检测**: 故障前 `[5,70)` tick 作为基线,对延迟、错误率、CPU、
   内存、连接池 5 项指标算均值/标准差,窗口内 z 值经 sigmoid 转异常分。
   综合分 = 45% 指标加权均值 + 55% 最强单指标,保证单指标打爆的根因不被稀释。
   低基数指标(错误率/利用率)有标准差下限,避免基线过平时 z 值爆炸。
3. **相关性加权随机游走**: 从告警入口出发,带重启(RWR)。走向下游的权重
   与"下游指标同入口的相关性"成正比并叠加边流量先验;允许回退上游与停在原地,
   低相关时回退权重衰减、停留与重启占比升高,游走被拉回真正的故障传导链。
4. **嫌疑排名**: 稳定访问概率(簇内归一化)× 来源修正后的异常程度,
   幂次组合让异常程度主导、访问概率在多个异常节点中定位源头。
5. **来源区分**: `self`(自身首发)/ `propagated`(下游传导)/ `reverse`
   (连接池饱和的反向传导),传导节点按跳数加深折扣,边缘网关额外压制。
6. **反向传导**: 模拟器强化"下游变慢→上游连接池占满→上游错误率先涨"的链路;
   检测侧以连接池越界 + 越界时序 + 下游相关性识别 reverse,排名仍指向下游根因。
7. **排名依据**: 每个候选附异常指标(基线值→窗口值、z 值)、入口到候选的
   传导路径及逐跳延迟/错误/连接相关性。
8. **双独立故障**: 异常子图按局部相关性连通分量切簇,单簇时再用"双异常中心
   低相关 + 图距离"二次分裂;每簇独立游走、簇内归一化,两个根因平等竞争排名。

## 故障模拟

- 32 个服务分 4 层(边缘网关/业务/能力/数据中间件),80+ 调用边,有向无环 + 跨层捷径。
- 正常态含日周期、AR(1) 噪声和偶发良性尖峰。
- 四类故障: 延迟飙升、错误注入、资源耗尽、连接池打满;异常沿入边反向 BFS
  逐跳衰减传导,连接池饱和按物理模型转化为超时错误,可开启反向传导强化。
- 共 420 个场景(总种子 `20261126`,完全可复现):
  单故障 300(四类各 75)+ 双独立故障 120,故障强度、目标、是否反向均随机。

## 实验结果(固定种子)

| 分组 | 样本 | RCA Hit@1 | RCA Hit@3 | 纯异常分 Hit@1 | 纯异常分 Hit@3 |
|---|---:|---:|---:|---:|---:|
| 全部 | 420 | **87.38%** | **95.71%** | 44.76% | 69.52% |
| 单故障 | 300 | **93.33%** | **97.67%** | 56.33% | 79.33% |
| 双独立故障 | 120 | **72.50%** | **90.83%** | 15.83% | 45.00% |
| 含反向传导 | 190 | **83.16%** | **94.74%** | 39.47% | 64.21% |
| 延迟飙升 | 75 | **86.67%** | **98.67%** | 5.33% | 52.00% |
| 错误注入 | 75 | **97.33%** | **100%** | 28.00% | 73.33% |
| 资源耗尽 | 75 | 93.33% | 96.00% | 96.00% | 96.00% |
| 连接池打满 | 75 | 96.00% | 96.00% | 96.00% | 96.00% |

关键结论:

- 整体 Hit@1 相对纯异常分排序提升 **42.6 个百分点**,延迟类故障提升 81.3 pp——
  纯异常分无法区分"自己出问题"和"被下游传导",随机游走 + 来源判定可以。
- 双故障 Hit@1 从基线 15.83% 提升到 72.50%,Hit@3 达 90.83%,两个独立根因都能进前列。
- 资源/连接池类故障异常信号本身已很显著,两种方法接近,符合预期。
- 420 个场景窗口检测偏差全部 ≤ 6 tick,且与注入记录逐条核对一致(Go 内建核对 +
  Python 独立交叉核对双重验证)。

## Web 页面包含的视图

- 依赖图: 节点颜色=异常分数,外圈=随机游走访问概率,边粗细=调用量,⭐ 标真实根因。
- 各服务异常分明细(综合分 + 5 项指标 z 值 + 首次越界 tick)。
- 随机游走后各服务稳定访问概率与最终根因排名(含 self/propagated/reverse 来源)。
- 点击排名查看依据: 异常指标、传导路径、逐跳相关性。
- 每次注入故障与定位结果对照、检测窗口与真实窗口偏差、故障簇划分、实验汇总命中率。
